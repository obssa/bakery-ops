# Traps: things that look fine locally and break in CI, in Docker, or on the shop floor

Read the row for whatever you are about to touch. Each trap has cost someone a day.

| Area | Trap | Do this instead |
|---|---|---|
| Ledger locking | `SELECT … FOR UPDATE` on a materialized view is impossible; `REFRESH MATERIALIZED VIEW` takes an exclusive lock; `CONCURRENTLY` cannot run inside a transaction | `stock_balances` is the lock target and the read path; the matview is the oracle and admin report, refreshed by a queued job; lock rows in ascending `(item_id, location_id)` to avoid deadlocks (ADR 0002) |
| First-row race | two processes making the first movement of the same new `(item, location)` both ran `SELECT … FOR UPDATE` on the missing `stock_balances` row (InnoDB gap locks do not conflict), then both `INSERT`ed: deadlock 1213 / `40001`. Laravel retries only an outermost transaction, so inside an `AuditedAction` the request failed (found in 2.2a, fixed in 2.2b) | never lock a row that may not exist: read which rows exist without a lock, create each missing one in the lock order with an upsert that updates nothing (it takes the row's exclusive lock whether it inserts or finds the other process's row; `INSERT IGNORE` would take a shared lock on the duplicate and two of those cannot both upgrade), then `FOR UPDATE` it; `tests/Gate/LedgerFirstMovementRaceTest.php` (forks, 30 rounds) |
| Reserved accounting | the doc lists movement reasons without reservation; `reserved` semantics undefined | one `MovementReason` class maps reason → (on_hand delta, reserved delta); `reservation` (+r), `reservation_release` (−r), `production_consume` / `sale` with `reservation_ref` (−r, −h) in one transaction; station lines consume at `ready`, display-case lines `sale` at `paid` |
| Units | recipe lines in display units, movements in base units | convert at recipe explosion only, 4 dp; property test with random unit factors round-trips |
| Live updates (polling, ADR 0009) | the live host has no WebSocket server; auto-increment `order_events` ids can become visible out of commit order, so a cursor jumps over a late commit; a timer per screen hammers a CPU-limited shared host; queued broadcasts pile up in a cron-drained queue | every screen subscribes through `LiveFeed`; cursor never advances past events younger than the overlap window (5 s), clients merge by line `version`; ETag + `If-None-Match` -> 304 from cheap indexed reads, and the ETag covers the unsettled tail (`OverlapCursor::fingerprint`: an ETag over the max id alone answers a late commit below it 304); compare `If-None-Match` weakly (Cloudflare turns strong ETags into `W/"..."` when it compresses); pause when hidden, back off when idle or offline; broadcast companions `broadcastWhen()` false under `BROADCAST_CONNECTION=null` (and `log`, which would still queue jobs); env() reads `null` as PHP null, so check the driver, not the string (`LiveTransport`) |
| Reverb in CI (only once a WebSocket transport is switched on) | server host and browser host differ; private channels need the bearer token; `docker compose --wait` needs health checks on every service and the PHP image has no `curl` | `REVERB_HOST=ws` for the app container, `NEXT_PUBLIC_REVERB_HOST=localhost` for the browser, `forceTLS:false`; Echo `authEndpoint` + `Authorization` header; health check with `php -r "fsockopen(...)"`; until then `e2e-p1` runs the polling transport and starts no `ws` service |
| Queues in e2e | stock-out → auto-request is queued; passes with `QUEUE_CONNECTION=sync` locally and fails in compose, or the reverse | feature tests: `Queue::fake` + a `sync` twin; compose always runs `worker`; e2e waits by polling the API, never `sleep` |
| Octane | singletons retaining `ActorContext` / branch across requests; Pest does not run under Octane so leaks are invisible in unit tests | `scoped()` bindings, `octane.flush` list, `OCTANE_WORKERS=1` in CI e2e, arch test on static state |
| Pest + Postgres | `RefreshDatabase` wraps each test in a transaction, so a second-connection `FOR UPDATE NOWAIT` test cannot see the rows; ParaTest needs CREATE DATABASE; triggers and matviews written in seeders vanish | `concurrency` group uses `DatabaseTruncation`; test DB role is superuser; raw SQL for triggers/matviews lives in migrations |
| Property tests | Pest has no shrinking | seeded generators + `->repeat()` / datasets; print the seed on failure; sequences ≤ 50 ops |
| Windows host | CRLF breaks `entrypoint.sh` and Pint; bind mounts are slow; host PHP 8.0 must never run artisan | `.gitattributes` `* text=auto eol=lf`; `core.autocrlf=false`; WSL2 backend; named volume for `vendor`; `composer.json` `config.platform.php = 8.3.x`; `scripts/php` refuses to run outside the container |
| Host Node vs Docker API | Next on `localhost:3000`, API in container on `localhost:8000`, Reverb on `localhost:8080` | bearer tokens (not Sanctum SPA cookies) so cross-origin and PWA offline stay simple; CORS allowlist for `localhost:3000` (ADR 0007) |
| Playwright | dev server hydrates late → flaky taps; service worker cache poisons tests; storage shared across contexts | test the built app via `webServer: next start`; `serviceWorkers: 'block'` except `p5-offline`; one `newContext()` per role; wait on API state |
| Idempotency | concurrent duplicates race before the key is stored; key scope unclear | Redis `SET NX` lock per key, store the response snapshot; scope `(branch, user, key)`; test with two parallel requests |
| Hash chain | non-canonical JSON (key order, NUMERIC formatting) breaks verification across PHP versions | canonical JSON: sorted keys, decimals as fixed-scale strings, UTC ISO-8601; chain per `(branch, location)`; `HashChain::verify` endpoint + test (ADR 0012) |
| Time zone | "daily" summaries and the Night shift 22:00–06:00 | store UTC; bucket by `Africa/Addis_Ababa`; shift instance `date` = local start date; boundary tests at 23:59 and 00:01 |
| spatie/permission | permission cache stale under Octane and in tests; temptation to use "teams" for branches | `forgetCachedPermissions()` in test setup; branch scoping via `BranchScoped`, not teams |
| NUMERIC through PDO | Postgres returns NUMERIC as string; `json_encode` of floats loses precision; `parseFloat` creeps into the frontend | brick/math end to end; API emits strings; TS types `string`; ESLint rule (ADR 0004) |
| activitylog vs audit_log | the package table is `activity_log`; the doc wants `audit_log` with extra columns | decide once in ADR 0001: own `audit_log` table written by `AuditedAction`, activitylog only for model diffs if at all |
| Seeds | later phases change seeds and break earlier gates | `DemoSeeder --phase=N` composes phase seeders; earlier gate projects always run; Phase 3 enforcement needs open shifts seeded for every station P1/P2 e2e touches |
| MinIO | signing host mismatch (`minio:9000` inside, `localhost:9000` from the browser); bucket missing | `AWS_ENDPOINT` vs `AWS_URL`; `mc` init container in `compose.ci.yml` |
| Pad location semantics | stock is per location but the pad is per branch | availability is computed at the location of the item's station (`locations.station_id`); display-case products at the `display_case` location; say so in the Phase 1 plan |
| OpenAPI from code | spec drifts when FormRequests / Resources are untyped | `dedoc/scramble`; `openapi-check` job; typed requests mandatory (PHPStan L8 helps) |
| "Wait for OK" with an unattended agent | agent proceeds without approval | `plan_approved: true` in `STATUS.json` is set only by a human commit; `gate_check --mode entry` refuses otherwise |
| GitHub Actions | service containers and compose fighting over ports in one job; Playwright browsers downloaded every run; e2e jobs that need the API image rebuilding it | module jobs use services only, e2e jobs use compose only; cache `~/.cache/ms-playwright`; `docker-build` job uploads the image tar as an artifact |
| Driver name checks | `DB::getDriverName()` is `mariadb` on the live host and in tests, `mysql` only on a real MySQL server; a branch written as `=== 'mysql'` silently skips MariaDB (the audit_log triggers did, caught 2026-10-19) | always `in_array($driver, ['mysql', 'mariadb'], true)`; AppendOnlyTest runs under the live driver |
| Composer in CI vs image | `shivammathur/setup-php` version drifting from the Docker image | pin both to the same `8.3.x`; the `doctor` script compares them |
| Phase scope creep | building Payments UI in Phase 1 because the schema is there | the step list in the manifest is the scope; anything else is a `TODO(p<N>)` marker, and `gate_check --mode done` forbids markers for the phase being closed |
