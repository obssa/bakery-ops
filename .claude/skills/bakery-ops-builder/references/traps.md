# Traps: things that look fine locally and break in CI, in Docker, or on the shop floor

Read the row for whatever you are about to touch. Each trap has cost someone a day.

| Area | Trap | Do this instead |
|---|---|---|
| Ledger locking | `SELECT … FOR UPDATE` on a materialized view is impossible; `REFRESH MATERIALIZED VIEW` takes an exclusive lock; `CONCURRENTLY` cannot run inside a transaction | `stock_balances` is the lock target and the read path; the matview is the oracle and admin report, refreshed by a queued job; lock rows in ascending `(item_id, location_id)` to avoid deadlocks (ADR 0002) |
| First-row race | two processes making the first movement of the same new `(item, location)` both ran `SELECT … FOR UPDATE` on the missing `stock_balances` row (InnoDB gap locks do not conflict), then both `INSERT`ed: deadlock 1213 / `40001`. Laravel retries only an outermost transaction, so inside an `AuditedAction` the request failed (found in 2.2a, fixed in 2.2b) | never lock a row that may not exist: read which rows exist without a lock, create each missing one in the lock order with an upsert that updates nothing (it takes the row's exclusive lock whether it inserts or finds the other process's row; `INSERT IGNORE` would take a shared lock on the duplicate and two of those cannot both upgrade), then `FOR UPDATE` it; `tests/Gate/LedgerFirstMovementRaceTest.php` (forks, 30 rounds) |
| Duplicate create inside a transaction | two uploads with one `client_uuid` raced: the loser's insert hit the unique key, and its `firstOrFail` read the snapshot taken before the winner committed, so it answered 404 (`FileUploadRaceTest`, 5.2b); PostgreSQL would abort the whole transaction on the duplicate | insert under a savepoint, then read the winner with a locking read (it sees the latest committed row); audit and answer 201 only for the request that stored the row, 200 for the other; prove it with a forked race test (30 rounds) |
| Reserved accounting | the doc lists movement reasons without reservation; `reserved` semantics undefined | one `MovementReason` class maps reason → (on_hand delta, reserved delta); `reservation` (+r), `reservation_release` (−r), `production_consume` / `sale` with `reservation_ref` (−r, −h) in one transaction; station lines consume at `ready`, display-case lines `sale` at `paid` |
| Units | recipe lines in display units, movements in base units | convert at recipe explosion only, 4 dp; property test with random unit factors round-trips |
| Live updates (polling, ADR 0009) | the live host has no WebSocket server; auto-increment `order_events` ids can become visible out of commit order, so a cursor jumps over a late commit; a timer per screen hammers a CPU-limited shared host; queued broadcasts pile up in a cron-drained queue | every screen subscribes through `LiveFeed`; cursor never advances past events younger than the overlap window (5 s), clients merge by line `version`; ETag + `If-None-Match` -> 304 from cheap indexed reads, and the ETag covers the unsettled tail (`OverlapCursor::fingerprint`: an ETag over the max id alone answers a late commit below it 304); compare `If-None-Match` weakly (Cloudflare turns strong ETags into `W/"..."` when it compresses); pause when hidden, back off when idle or offline; broadcast companions `broadcastWhen()` false under `BROADCAST_CONNECTION=null` (and `log`, which would still queue jobs); env() reads `null` as PHP null, so check the driver, not the string (`LiveTransport`) |
| Reverb in CI (only once a WebSocket transport is switched on) | server host and browser host differ; private channels need the bearer token; `docker compose --wait` needs health checks on every service and the PHP image has no `curl` | `REVERB_HOST=ws` for the app container, `NEXT_PUBLIC_REVERB_HOST=localhost` for the browser, `forceTLS:false`; Echo `authEndpoint` + `Authorization` header; health check with `php -r "fsockopen(...)"`; until then `e2e-p1` runs the polling transport and starts no `ws` service |
| Queues in e2e | stock-out → auto-request is queued; passes with `QUEUE_CONNECTION=sync` locally and fails in compose, or the reverse | feature tests: `Queue::fake` + a `sync` twin; compose always runs `worker`; e2e waits by polling the API, never `sleep` |
| Octane | singletons retaining `ActorContext` / branch across requests; Pest does not run under Octane so leaks are invisible in unit tests | `scoped()` bindings, `octane.flush` list, `OCTANE_WORKERS=1` in CI e2e, arch test on static state |
| Pest + Postgres | `RefreshDatabase` wraps each test in a transaction, so a second-connection `FOR UPDATE NOWAIT` test cannot see the rows; ParaTest needs CREATE DATABASE; triggers and matviews written in seeders vanish | `concurrency` group uses `DatabaseTruncation`; test DB role is superuser; raw SQL for triggers/matviews lives in migrations |
| Property tests | Pest has no shrinking | seeded generators + `->repeat()` / datasets; print the seed on failure; sequences ≤ 50 ops |
| Windows host | CRLF breaks `entrypoint.sh` and Pint; bind mounts are slow; host PHP 8.0 must never run artisan | `.gitattributes` `* text=auto eol=lf`; `core.autocrlf=false`; WSL2 backend; named volume for `vendor`; `composer.json` `config.platform.php = 8.3.x`; `scripts/php` refuses to run outside the container |
| Git worktrees | in a linked worktree `.git` is a file, not a directory, so a script that checks for a `.git` directory decides it is not in a repository (5.6a) | accept either (`gate_check.is_git_repo`), or ask `git rev-parse --git-dir` |
| Eloquent `except()` | on an Eloquent collection `except($keys)` drops the models whose **primary key** is in `$keys`, not the entries under those collection keys, so `$devices->keyBy('fingerprint')->except('demo-bridge-1')` removes nothing (5.6b, `Phase5SeederTest`) | filter on the attribute (`->filter(fn ($d) => ...)`, `->reject(...)`) or call `->toBase()` before a key-based `except` |
| Host Node vs Docker API | Next on `localhost:3000`, API in container on `localhost:8000`, Reverb on `localhost:8080` | bearer tokens (not Sanctum SPA cookies) so cross-origin and PWA offline stay simple; CORS allowlist for `localhost:3000` (ADR 0007) |
| Playwright | dev server hydrates late → flaky taps; service worker cache poisons tests; storage shared across contexts | test the built app via `webServer: next start`; `serviceWorkers: 'block'` except `p5-offline`; one `newContext()` per role; wait on API state |
| Playwright `testMatch` | a project's `testMatch` regex is matched against the spec's absolute path, and CI checks out into `.../bakery-ops/bakery-ops/`, so `/ops/` took every spec in `e2e/p5` (5.3c: 5.5a's `errors-on` ran under `p5-device`) | anchor on the file name: `/ops-live\.spec\.ts$/`, or `/[\\/]print[^\\/]*\.spec\.ts$/` for a family of files; never a bare word a folder name can hold |
| Offline specs in CI | CI serves `next start`, which has no `sw.js` (the shell cache is built only for the static export the live host serves), so a reload spec there cannot prove the service worker (5.2a) | the `p5-offline` reload aborts every API call and proves only that the queue lives in IndexedDB; a spec says what it proves and claims nothing about the shell cache |
| Idempotency | concurrent duplicates race before the key is stored; key scope unclear | Redis `SET NX` lock per key, store the response snapshot; scope `(branch, user, key)`; test with two parallel requests |
| Hash chain | non-canonical JSON (key order, NUMERIC formatting) breaks verification across PHP versions; the head of a place may not exist yet (first-row race again); a locked row changed by someone with the database | canonical JSON: sorted keys, decimals as fixed-scale strings, UTC ISO-8601 with six fraction digits; chain per `(branch, location)` claimed by the unique `(branch_id, location_id, chain_seq)` with a retry loop, never a lock on the head; the exact bytes are stored next to the hash; triggers on both engines; nightly `shifts:verify-chain`; `scripts/verify_chain.py` is a second implementation (ADR 0012). Tamper tests drop triggers (DDL commits), so they live in `tests/Gate/` with `CommitsForConcurrency` |
| Shift rules | with the rules on every writer of `on_hand` at a tracked station needs an open shift: fixtures, seeders and e2e helpers that forgot it fail with `inventory.shift.required` or `payments.shift.required`; a station whose shift is `counting` refuses movements too (the freeze); carried live-E2E shifts are never closed | `Tests\Support\Shifts::ensureOpen`, `DemoShifts::ensureOpen`, `e2e/support/shifts.ts` (`ensureOpenShift`, which also declares a till's drawer when it counts); the `rules-off-gates` CI job runs the Phase 0-2 gates with all three rules off, which is the state after the kill switch |
| Settling ETag | an ETag over the newest id answers 304 to a reader whose cursor sits below a late commit; and a test that writes stock and then expects the same tag fails inside the 5 s overlap window | the tag adds `settling` while the newest movement is younger than the overlap window (`OverlapCursor`); tests that expect a 304 or the same tag after writing stock first travel past the window |
| Settling ETag (Phase 4 feeds) | the payments list (`Payments::fingerprint()`) and every reader that writes a payment, a stock movement or a summary inside the 5 s window gets a new tag on the next read, so a test asserting a `304` right after its fixture flakes by the clock; a polled list that keeps answering 304 would also keep handing out signed URLs that expire | the fingerprint carries `settling` while the newest row is younger than the window; a test travels `OverlapCursor::fromConfig()->windowSeconds() + 1` seconds before asserting a 304 or an unchanged tag; the payments list's tag adds a bucket of half the signed URL's life (step 4.3b) |
| OpenSpout formula cells | `Row::fromValues()` makes a formula cell of any text that starts with `=`, so a typed reference or dispute reason runs as a formula in the admin's Excel (found in 4.4d in 4.3e's payments export) | build every text as a text cell (`Cell\StringCell`); figures as number cells holding the decimal string (`Shared\Exports\XlsxFile`, a marker rewritten after OpenSpout closes the file), never a PHP float; CSV gets the formula guard and the byte-order mark |
| One query key, one shape (web) | two screens that share a TanStack Query key with different answer shapes crash the second one on client navigation (`stations.filter is not a function`: the admin overview stored the `Me` object under `["me-work-stations"]` and the Shifts page read it as an array; PR #71, live 2026-10-26) | one query key per answer shape, read through one hook (`useWorkStations`); the Playwright test holds the second page's request so it fails without the fix every time |
| New fields on a PUT | a till that cached the receipt settings screen before 5.3c sends `PUT /receipt-settings` without `paper_width_mm`; a PUT that resets a missing field to its default turns a 58 mm printer back to 80 mm | a field added to an existing `PUT` is optional, and left out the saved value stays; test the old body against a row that holds a changed value |
| IndexedDB upgrades | a database first opened without a version is version 1 with no store, so an upgrade that branches on the old version number skips creating stores (5.2b) | create every store that is missing, looking at the stores the database has, not at the old version (`upgradeDb`); the tablet's queued writes stay |
| Redis unique locks under seeding | a seeder that queues `ShouldBeUnique` jobs on the dev or CI Redis queue (no worker, or a worker in real time) leaves their unique locks held for the lock's life (`EvaluateBalance`: 10 minutes) while the seed moves its own clock, so the history's own evaluations of the same balance are swallowed (the 4.6a stock-outs never opened); tests run `sync` and the `array` cache, whose locks expire in the seeded clock, so they do not show it | from Phase 4 the whole anchored seed runs on the `sync` queue (`DemoClock::around`, put back afterwards); jobs a seed must not run per write are held on a `BusFake` and run once where they belong (`Demo\DemoAlerts`); `Phase4SeederTest` asserts the `jobs` table is empty |
| The live host under load | the shared host drops connections (ECONNRESET, a body read that fails after the headers) while its load average is 10 to 12; two `@live` flows failed that way after the 4.5d deploy, and a reboot during a deploy gave Cloudflare 522s for minutes | the e2e API client retries a request whose connection dropped, 3 attempts about 1 s and 3 s apart with one Idempotency-Key per logical request, never an HTTP answer (`e2e/support/api.ts`, `networkRetry`); a deploy that fails on a reboot is re-run, not "fixed" |
| Load tests on the CI stack | the image's `artisan serve` answers one request at a time and, being the CLI, runs without OPcache, so k6 measured the dev server (polls p95 351 ms on a slow runner, over the 300 ms threshold); a queue worker started before the seed races `migrate:fresh` (5.5d) | `compose.perf.yml`: PHP's built-in server on Laravel's router file with `PHP_CLI_SERVER_WORKERS=8` and OPcache on; `php artisan optimize` before k6, as a release does, and `optimize:clear` before the Pest after-checks so they read `phpunit.xml`; the worker starts after the seed |
| k6 schedules and logins | a `constant-arrival-rate` scenario of exactly 600 s at one every 2 s also starts an iteration at 600 s (a 301st order); a setup that signs every virtual user in meets `/login`'s 10 a minute per address (a pad's short code: 30 a minute) (5.5d) | duration N x interval minus 1 s (599 s, last start at 598 s) and thresholds on the count (`orders_paid == 300`, `dropped_iterations == 0`); `setup()` signs in a few accounts once (seven in `load.k6.js`) and shares their tokens |
| Perf thresholds on shared runners | `perf-load`'s poll p95 moved with the runner, not the code: 206 ms and 351 ms (failed) without OPcache on two runners, 171 ms and then 45 ms with it; the 4-core runner is close to busy at about 61 requests a second (5.5d) | read a failed run's per-feed figures and the runner before touching code; the plan's thresholds stay; if `perf-load` turns flaky the choices are a larger runner (paid: Ramin's call) or fewer devices per job |
| Error tracking in tests | the Sentry PHP SDK sends the source lines around in-app frames, so a secret written whole in the test file shows up in the captured event and the "scrubbed" assertion fails on the test's own code (5.5a) | write planted secrets in halves joined at run time; capture through the SDK's own `http_client` option into a fake ingest (`FakeSentryIngest`), so the real client, `before_send` and serialisation run and nothing leaves the process |
| Static export record pages | the web app is a static export under `/app` (ADR 0006): a dynamic segment (`/orders/[id]`) cannot be prerendered for ids that do not exist at build time, and a deep link to one 404s on the host | record pages take `?id=` on a fixed route (`/admin/analytics/product?id=`, the order record, the audit drawer's `?id=`), the id and the filters live in the address (`lib/deeplink.ts` knows each page); the static-export CI step checks the prerendered files |
| Pest in the API image | the image is built from a git checkout, so it has no `.env` (compose gives the variables); phpdotenv reads the missing file with `@file_get_contents` and PHPUnit still reports it as a warning on every test that boots Laravel, so a container run says `14 warnings, 1 passed` for a green group (found in 4.6b; `files-s3` showed it since 4.2b) | `docker compose exec -T app touch .env` before `vendor/bin/pest` in a container job, then treat a warning like a skip (the `gate-p4` job) |
| PHPUnit pins the test database | phpunit.xml's `<server name="DB_DATABASE" value="bakery_test"/>` is written into `$_SERVER` unconditionally, so `docker compose exec -e DB_DATABASE=bakery app vendor/bin/pest` still runs on `bakery_test`: a gate test that should read a seeded database reads an empty one (the 4.6a note assumed the container's value wins) | a test that reads a seeded database points its own connection at it (`Tests\Support\SeededGate`: `GATE_SEED_DATABASE`, `config(...)` and `DB::purge`), never with `RefreshDatabase`/`DatabaseTruncation`, and fails, never skips, when the seed is missing; the other tests of the process keep `bakery_test` |
| A test that needs one environment's path | `->skip(` is banned in module tests (`gate_check --mode done`) and the gate jobs fail on a skip or a warning, so "skip when the file or binary is missing" turns a gate red, or hides the hole where no gate looks | take the path from an environment variable with a default that works on a runner checkout, and fail, naming where it looked, when it is missing: `Phase5GateTest` reads the go-live checklist from `GATE_REPO_ROOT` (the `gate-p5` job copies `docs/` and `scripts/` into the container, since the image holds `apps/api` only), defaulting to two folders above `base_path()` |
| Device enforcement in the CI stack | `compose.ci.yml` turns `IDENTITY_REQUIRE_DEVICE` on for `app` and `worker`, so a Pest run inside that container meets a refusal on every station route its test did not enrol for (5.1b) | Pest runs in the stack (`gate-p4`, `gate-p5`, `files-s3`, `backup-drill`, `perf-load`) pass `-e IDENTITY_REQUIRE_DEVICE=false`: tests keep the code default (off) and turn it on where they test it; Playwright enrols each role's device in global setup |
| Memory in one big test process | `api-arch` runs some 3 400 tests in one PHP process that keeps every test case and the arch plugin's parsed sources; at 1 GB it ran out near the end, three times (5.5a); not a leak (about 64 KB a test on main too) | `phpunit.xml` allows 2 GB; when a job nears that, split its groups over two jobs instead of raising the limit again |
| Golden images | a raster golden drawn on a developer PC, or compared dot for dot, fails in CI: two FreeType builds (2.13 on the runner, 2.12 in the PHP image's bundled GD) place glyphs a dot or two apart, and a one-dot tolerance still failed the first CI run (1.6 %) (5.3a) | draw goldens in CI's own environment, its fonts and libraries (`UPDATE_RECEIPT_GOLDENS=1` there, never on a PC), and compare within a measured tolerance (`ReceiptRasterTest` through `EscPosEmulator`: a two-dot neighbourhood, 0.5 % of the dots, 2 rows of height) |
| Login rate limit | `/login` allows 10 a minute per IP, so a Playwright worker that restarts after a failed test and logs in again hits `429` | `e2e/support/global-setup.ts` names a per-run token file (`E2E_TOKEN_FILE`, system temp, never under `test-results`) that `Api.login` reads and writes; a 429 waits `Retry-After` and retries once |
| Counts and the catalog | a draft count that lists an item deleted (or switched off) after the draft was made blocks the station: submit refused, and a draft cannot be rejected | submit drops the lines of deleted items (audit `count.lines_dropped`, `dropped_item_ids` in the answer; the lines trigger allows DELETE of draft lines); a switched-off item that still has stock is countable ("count what is on the shelf"); approving a variance on a deleted item is `409 shifts.count.item_unavailable` |
| Time zone | "daily" summaries and the Night shift 22:00–06:00 | store UTC; bucket by `Africa/Addis_Ababa`; shift instance `date` = local start date; boundary tests at 23:59 and 00:01 |
| spatie/permission | permission cache stale under Octane and in tests; temptation to use "teams" for branches | `forgetCachedPermissions()` in test setup; branch scoping via `BranchScoped`, not teams |
| NUMERIC through PDO | Postgres returns NUMERIC as string; `json_encode` of floats loses precision; `parseFloat` creeps into the frontend | brick/math end to end; API emits strings; TS types `string`; ESLint rule (ADR 0004) |
| activitylog vs audit_log | the package table is `activity_log`; the doc wants `audit_log` with extra columns | decide once in ADR 0001: own `audit_log` table written by `AuditedAction`, activitylog only for model diffs if at all |
| Seeds | later phases change seeds and break earlier gates; a history written into the past of a branch that already has movements rewrites what the append-only ledger has shown | `DemoSeeder --phase=N` composes phase seeders; earlier gate projects always run; every earlier seeder opens the shifts it needs (`DemoShifts::ensureOpen`); the Phase 3 history is written only on a fresh branch, with the clock moved by `Demo\DemoClock` (Carbon and CarbonImmutable both), and `bakery:seed-demo` on a branch that already holds movements does only the "today" part and says so |
| MinIO (portability job only) | signing host mismatch (`minio:9000` inside, `localhost:9000` from the browser); bucket missing | `AWS_ENDPOINT` vs `AWS_URL`; `mc` init container in `compose.ci.yml` |
| Pad location semantics | stock is per location but the pad is per branch | availability is computed at the location of the item's station (`locations.station_id`); display-case products at the `display_case` location; say so in the Phase 1 plan |
| OpenAPI from code | spec drifts when FormRequests / Resources are untyped | `dedoc/scramble`; `openapi-check` job; typed requests mandatory (PHPStan L8 helps) |
| "Wait for OK" with an unattended agent | agent proceeds without approval | `plan_approved: true` in `STATUS.json` is set only by a human commit; `gate_check --mode entry` refuses otherwise |
| GitHub Actions | service containers and compose fighting over ports in one job; Playwright browsers downloaded every run; e2e jobs that need the API image rebuilding it | module jobs use services only, e2e jobs use compose only; cache `~/.cache/ms-playwright`; `docker-build` job uploads the image tar as an artifact |
| Parallel PRs | Phase 5 had several step branches open at once, each green on the base it was cut from; once another PR merges, green on the old base proves nothing about the combination (a new spec, route, migration or seed it never ran with) | before main moves, merge `origin/main` into the branch (an ordinary merge commit, never a rebase or a force-push), push, let the full CI run on the merged head, then fast-forward `main` to it; the next PR in line does the same with the new main (ci-cd.md) |
| Generated docs in a merge | `docs/openapi.json` conflicts whenever two branches change routes; a hand-merged spec is valid JSON that matches no code, and `docs/erd.dbml` merged by picking one side loses the other side's tables | never hand-merge them: take either side, re-export the spec as the `openapi-check` job prints (`scripts/artisan scramble:export --path=../../docs/openapi.json`, against a migrated database) and add every table `erd-check` lists as missing; commit the result with the merge |
| Shallow clones and sign-offs | `actions/checkout` fetches one commit: `check_invariants.py --signoffs` (who committed each file in `docs/go-live/signoffs/`) and `gate_check`'s `done_commit` ancestry cannot be answered, so they fail | `fetch-depth: 0` on `invariants` and the gate jobs; sign-offs are made only in GitHub's web editor (committer `GitHub <noreply@github.com>`), never by a local commit; D16's sign-from-the-PC fallback is not built, because nothing can tell it apart from an agent's commit |
| Driver name checks | `DB::getDriverName()` is `mariadb` on the live host and in tests, `mysql` only on a real MySQL server; a branch written as `=== 'mysql'` silently skips MariaDB (the audit_log triggers did, caught 2026-10-19) | always `in_array($driver, ['mysql', 'mariadb'], true)`; AppendOnlyTest runs under the live driver |
| Image build registries | `pecl install redis` (unpinned) failed every image build for hours when pecl.php.net was unreachable on 2026-10-21, which skipped every e2e and gate job | build extensions from a tagged source release pinned by version and sha256 (`docker/php.Dockerfile` `PHPREDIS_VERSION` / `PHPREDIS_SHA256`); never fetch an unpinned package at image build time |
| Composer in CI vs image | `shivammathur/setup-php` version drifting from the Docker image | pin both to the same `8.3.x`; the `doctor` script compares them |
| Phase scope creep | building Payments UI in Phase 1 because the schema is there | the step list in the manifest is the scope; anything else is a `TODO(p<N>)` marker, and `gate_check --mode done` forbids markers for the phase being closed |
